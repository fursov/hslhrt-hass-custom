# v0.9.0 — Release notes (draft)

Home Assistant integration for HSL stop departures, configured-stop map
markers and optional live HFP vehicle tracking.

## Changes since GitHub tag v0.8.2

- **Local minute-by-minute timetable refresh (PR17):** The next route,
  next-arrival timestamp, minutes-until-arrival value and timetable
  attributes update each minute using the last Digitransit response.
- **Automatic departure rollover:** After the expected arrival time,
  the next already-fetched departure becomes active. If none remain,
  affected sensor values become `unknown` until new data is fetched.
- **No additional network load:** Local sensor refreshes do not increase
  Digitransit HTTP polling or HFP MQTT activity. Configured polling
  intervals (1–30 minutes) remain unchanged.
- **HA lifecycle safety:** Minute timers are cancelled on entity
  removal/unload; regression tests exercise the behavior on actual
  Home Assistant 2026.10.2 and Python 3.14.

## Available map features

The combined map also supports two independent geolocation sources:

- `hslhrt`: live HFP vehicles with emoji/route labels, where GPS is fresh.
- `hslhrt_stops`: configured physical stops with circle-style icons,
  visible even without MQTT/GPS tracking (PR16).

**Historical note:** PR16 was already included in GitHub tag **v0.8.2**.
That tag points to commit `56b30a1`, whose manifest unusually declared
`0.9.0`. Do not move or replace the existing tag. This release restores
the correspondence between the GitHub tag and manifest version.

## Compatibility and upgrade

- Minimum Home Assistant Core: **2026.10.2** (Python 3.14).
- Existing stop configurations, unique IDs and entity IDs are unchanged.
- Digitransit API subscription key and HFP setup are unchanged.
- No config-entry migration or additional dependencies.
