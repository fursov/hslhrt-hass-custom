# v0.9.5 — Release notes

Home Assistant custom integration for Helsinki Regional Transport (HSL HRT).
This release improves stop setup and Home Assistant integration discovery.

## Changes since v0.9.4

### Multiple routes during initial setup (PR28)

The initial stop **Routes** field now accepts multiple route numbers separated
by commas, whitespace or a mixture of both:

```text
158, 530
158 530
158,530
```

All three select the same two routes. Input is normalized, duplicates are
removed and the same logical selection produces the same stable config-entry
identity regardless of route order or separator. Every requested route must
serve the configured stop. Use `ALL` alone to select every route; mixing
`ALL` and explicit route numbers is rejected.

The existing **Configure → Routes** multiple-selection dropdown continues
to work and automatically preselects the routes from the initial setup.
Existing single-route and `ALL` entries, their unique IDs, sensors and
dashboard entities remain compatible.

### Home Assistant category (PR27)

The integration manifest now declares
`vehicles_transport.public_transport`, the recognized Home Assistant
public-transport category. The integration's version is `0.9.5`.

### Release history

The changelog now correctly labels the previously published v0.9.4 and
v0.9.2 releases with their publication dates.

## Compatibility

- Minimum Home Assistant Core: **2026.10.2**, as declared in `hacs.json`.
- No manual migration is necessary for existing entries.
- No new dependencies, permissions or Digitransit subscription keys.
- Realtime departure predictions, GPS/HFP tracking, multi-stop vehicle
  deduplication, update intervals and dashboard popup attributes retain
  their existing behavior.
